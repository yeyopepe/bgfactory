- **Nombre**: Eliminar tipo "Ficha" y renombrar "Carta" a "Carta/Ficha"
- **Código**: 00087

## (a) Anotaciones funcionales

- Fuera de alcance: no se modifica el modelo de datos del tipo `'carta'` más allá de lo estrictamente necesario para poder mapear una `'ficha'` sobre él (no se añaden campos nuevos a `DEFAULT_CARTA_PROPERTIES`, no se toca el editor de cartas, mazos, volteo, ni cualquier otro comportamiento ya existente de `'carta'`). No se modifica el resto del flujo de importación (selección, modo add/overwrite, comportamiento ante id duplicado, informe de referencias rotas de `mergeImportedGame`) salvo el punto de inserción del nuevo aviso.
- No hubo dudas nuevas que resolver con el usuario durante la planificación — las siete dudas de alcance ya están resueltas en `description.md`.
- Anotación de causa raíz: como el tipo `'ficha'` desaparece del todo (se migra siempre a `'carta'` en cualquier punto de carga), todo el código específico de `'ficha'` en la capa `ui` (rama de renderizado, tab de la modal de configuración, entrada en la modal de alta, defaults de creación, CSS) queda muerto y se elimina — no se deja como código inalcanzable. Es coherente con que este `xxxx` es un `change`, no un `fix`: no aplica la restricción de alcance mínimo de `ms-fix`.

## (b) Solución técnica

1. **`src/core/fichaMigration.js`** (nuevo módulo, capa `core`, sin dependencias de DOM ni de `ui/*` — mismo criterio que `core/importMerge.js`): implementa la migración de un componente `'ficha'` a `'carta'` según el mapeo de `description.md`.
   - Constantes locales propias del módulo con los valores por defecto **legados** de `'ficha'` (`forma: 'circular'`, `bordeColor: '#000000'`, `bordeGrosor: 2`, `fondoTipo: 'color'`) — deliberadamente *no* importadas desde `ui/componentModal.js` (que además va a perder `DEFAULT_FICHA_PROPERTIES` en el paso 4): así este módulo de `core` no depende de `ui`, respetando `ARCHITECTURE.md` sección 2.
   - Importa `CARD_PROPORTIONS`/`getDesignSize` de `core/cardProportions.js` (dependencia core→core, permitida).
   - `export function convertFichaToCarta(component)`: función pura, devuelve siempre `{ component: <componente carta>, error: string | null }` (nunca lanza, nunca devuelve `null` en `component`, para que el llamante en el arranque pueda usarlo sin más incluso si hay `error`):
     - Si `component.properties` no existe o no es un objeto: `error = 'Falta la configuración de diseño (properties)'`, `component` resultante con `properties` vacías (fallback razonable, ver más abajo).
     - `forma`: `'circular'` → `proporcion: 'circular'`; `'cuadrada'` → `proporcion: '1:1'`; `undefined` → `proporcion: 'circular'` (mismo default que tenía `'ficha'`, no es un error); cualquier otro valor → `error = 'Forma no reconocida ("' + forma + '")'` y se usa `'circular'` como fallback para poder seguir construyendo un resultado igualmente.
     - Construye un único objeto "cara" (mismo shape que `caraFrontal`/`caraTrasera` de `DEFAULT_CARTA_PROPERTIES`, con `transparenciaImagen: 0`) con `bordeColor`/`bordeGrosor` tomados de la ficha (con los defaults legados si faltan).
     - Según `fondoTipo`:
       - `'imagen'` con `imagenResourceId` presente: si `ajusteImagen` no es un objeto o `zoom`/`posX`/`posY` no son números finitos → `error = error ?? 'Ajuste de imagen con datos incompletos'` (sin copiar imagen al resultado); si es válido, copia `imagenResourceId`/`ajusteImagen` a la cara.
       - `'texto'`: si `properties.texto` no es un string → `error = error ?? 'Falta el texto de la ficha'`; si es un string no vacío, añade un único `textBox` que ocupa toda la carta: `{ id: crypto.randomUUID(), contenido: texto, fuenteResourceId: null, tamañoFuente: <valor fijo razonable, p. ej. 24, en unidades de diseño>, color: '#000000' (la ficha no tenía color de texto configurable, siempre negro), x: 0, y: 0, width: designWidth, height: designHeight }`, usando `getDesignSize(proporcion)` ya calculada.
       - `'color'` (o `fondoTipo` ausente): no añade nada a la cara — la pérdida del color de fondo sólido es intencional y silenciosa (no es un `error`), tal como pide `description.md`.
       - Cualquier otro valor de `fondoTipo` no reconocido: tratarlo igual que `'color'` (silencioso, sin marcar error) — solo la `forma` no reconocida y los datos de imagen/texto incompletos cuentan como error, según las preguntas de alcance resueltas.
     - El mismo objeto "cara" (clonado, no compartiendo referencia) se usa para `caraFrontal` y `caraTrasera`.
     - `properties` final: `{ proporcion, deckId: null, caraActual: 'frontal', caraFrontal, caraTrasera }`.
     - Componente resultante: `{ ...component, type: 'carta', properties }` — el resto de campos de nivel superior (`id`, `x`, `y`, `width`, `height`, `bloqueado`, `mostrarTooltip`, `subirAlMoverInteractuar`, `order`) se mantienen sin cambios (no hace falta ajustarlos: `subirAlMoverInteractuar`/`bloqueado` ya tenían en `'ficha'` los mismos valores por defecto que en `'carta'`, y `width`/`height` existentes son válidos también para `'carta'`, incluida la proporción `'circular'`, que admite cualquier tamaño).
   - `export function migrateFichaComponents(components)`: mapea la lista sustituyendo cada componente con `type === 'ficha'` por `convertFichaToCarta(component).component` (ignorando `error` deliberadamente — uso exclusivo del arranque/carga silenciosa); el resto de componentes se devuelven tal cual.

2. **`src/core/state.js`, `loadComponents(components)`**: antes de `compactOrders(components)`, pasar la lista por `migrateFichaComponents` (import de `core/fichaMigration.js`, dependencia core→core). Cubre los tres puntos de entrada que ya pasan por aquí: autoguardado de `localStorage`, semilla embebida (HTML exportado con estado embebido) y el resultado final de una importación (`loadComponents(components)` en `ui/editModeToggle.js`, ver punto 3) — igual que ya hace hoy la migración silenciosa de `order`.

3. **`src/ui/editModeToggle.js`, flujo de "Importar"** (`importComponentsFromFile` → `onAccept` de `openImportConfirmModal`): insertar la validación de conversión de fichas **antes** de llamar a `mergeImportedGame`, sobre `selectedComponents = byIds(result.components, componentIds)` (la selección ya confirmada, coincide con el punto "¿Hay fichas seleccionadas?" del diagrama de `description.md`):
   - Nueva función local `convertSelectedFichas(components)`: recorre `components`, y para cada uno con `type === 'ficha'` llama a `convertFichaToCarta` (`core/fichaMigration.js`); si `error`, añade `{ id: component.id, motivo: error }` a una lista de errores y **excluye** ese componente del resultado; si no hay error, sustituye el componente por el `component` convertido (ya `type: 'carta'`). Los componentes que no son `'ficha'` pasan tal cual. Devuelve `{ components, errors }`.
   - Con `errors.length === 0`: seguir exactamente igual que hoy (llamar a `mergeImportedGame` con `selectedComponents` ya convertido en vez del original — los que eran `'ficha'` ya son `'carta'`, el resto sin cambios).
   - Con `errors.length > 0`: no llamar a `mergeImportedGame` ni a ningún `loadX` todavía; abrir `ui/fichaConversionErrorModal.js` (punto 4) con `errors` y dos callbacks:
     - `onAbort`: no hacer nada más — la partida actual queda intacta, como pide `description.md`.
     - `onContinue`: proceder con el resto del flujo actual (`mergeImportedGame` → `loadComponents`/`loadResources`/`loadDecks` → informe de importación si aplica) usando `components` (ya sin las fichas con error, con las convertidas correctamente ya como `'carta'`).
   - Extraer el bloque `mergeImportedGame(...) + loadComponents/loadResources/loadDecks + informe` a una función local (p. ej. `applyImportedSelection(components)`) para poder invocarla tanto desde el camino sin errores como desde `onContinue`, sin duplicar el código.

4. **`src/ui/fichaConversionErrorModal.js`** (nuevo módulo `ui`): `export function openFichaConversionErrorModal({ errors, onAbort, onContinue })`. Sigue el patrón visual de `design_aviso-errores-conversion-fichas.html` (referencia solo visual, sin reutilizar su HTML/CSS literal) combinando patrones ya existentes en el código real:
   - Cabecera con icono de error (`.modal__header--error`/`.modal__error-icon`, mismo patrón que `ui/errorModal.js`, sección 12.1 de `STYLE_BIBLE.md`), título "Errores al convertir fichas".

   - Pie con dos botones, mismo patrón que `ui/deckDeleteConfirmModal.js` (dos acciones, no un único "Cerrar"): `.btn-cancel` "Abortar importación" (invoca `onAbort()` y cierra) y `.btn-accept` "Continuar sin esas fichas" (invoca `onContinue()` y cierra).
   - Mismo patrón de `overlay`/cierre por click fuera que el resto de modales de la app.
   - Necesita su propia clase de bloque ancho (`max-width: 640px`, igual que `.import-report-modal`/`.element-selection-modal`) — ver (d).
