## (b) Technical solution

- [x] **`src/ui/icons.js` (nuevo) — módulo centralizado de iconos.** Define, por cada una de las ~40 claves semánticas del inventario (`design_data_inventario-iconos.md`), el `<path>`/contenido interno del icono Lucide correspondiente (lienzo de referencia `viewBox="0 0 24 24"`, grosor `stroke-width="2"`, `stroke="currentColor"`, sin color fijo — salvo el caso puntual de relleno `fill="currentColor"` que ya usan hoy los puntos del dado en `componentTypeModal.js`, que se mantiene igual). Reutiliza el dibujo oficial de cada icono Lucide (copiado literal, sin instalar el paquete `lucide`, sin CDN — coherente con `008-code-conventions.md`). Expone:
  - `iconSvg(name, { size, strokeWidth } = {})` → `string` con el `<svg>` completo (`viewBox="0 0 24 24"`, `width`/`height` = `size` si se pasa o el tamaño por defecto del contexto llamador, `class="icon-frame"` para mantener el hook de tamaño existente).
  - `iconEl(name, opts)` → `SVGElement` (implementado como `document.createElementNS(...)` + `innerHTML` del `iconSvg` interno, igual patrón que ya usan hoy los menús/`.align-group`).
  - `ICON_SIZE` con las tres constantes con nombre: `toolbar: 20`, `menu: 16`, `zoom: 18` (px) — el inventario fija estos valores como el "punto de partida" del criterio; el tamaño visible real por contexto se preserva 1:1 cambiando el `size`/CSS de cada sitio, nunca reescalando el propio módulo.
  - Nombre inexistente en el mapa → en desarrollo, `iconSvg`/`iconEl` devuelven un recuadro de aviso visual (SVG de placeholder con signo de exclamación, sin romper la pantalla) — no se lanza excepción.
  - El caso `chevron-down` (flechita de "Exportar") entra como una clave más del inventario, sin tratamiento especial.
- [x] **`src/ui/editModeToggle.js` — sustituir las constantes `ICON_*` inline.** `ICON_FIT`, `ICON_SETTINGS`, `ICON_IMPORT`, `ICON_EXPORT`, `ICON_EXPORT_CHEVRON`, `ICON_MODE_PLAY` se eliminan; cada punto donde se usaban (`iconTextButton(ICON_IMPORT, ...)`, `button.innerHTML = ICON_FIT`, `insertAdjacentHTML('beforeend', ICON_EXPORT_CHEVRON)`, etc.) pasa a llamar `iconSvg('fit-view')`/`iconSvg('settings')`/`iconSvg('import')`/`iconSvg('export')`/`iconSvg('chevron-down')`/`iconSvg('mode-play')` respectivamente, sin tocar `iconTextButton`, el `insertAdjacentHTML` ni el orden de construcción del DOM.
- [x] **`src/ui/appTitle.js` — sustituir el lápiz inline.** El SVG del lápiz de "Editar título" pasa a `iconSvg('edit-title')` (o `iconEl` si el sitio inserta nodo), sin tocar la clase `.app-title__pencil` ni su lógica de visibilidad en `:hover`.
- [x] **`src/ui/componentList.js` / `src/ui/resourceList.js` / `src/ui/tagList.js` — sustituir el aspa de limpiar filtro.** Cada uno de los tres pasa a usar `iconSvg('clear')` en el sitio donde hoy define el SVG del aspa, sin tocar el resto del buscador.
- [x] **`src/ui/tableColumnMenu.js` — sustituir el embudo.** El SVG del embudo (hoy `viewBox="0 0 16 16"`) pasa a `iconSvg('filter', { size: 16 })` (o el tamaño `menu` por defecto si coincide), sin tocar el resto del menú de columna.
- [x] **`src/ui/cardTextBoxModal.js` — sustituir los 9 SVG de alineación/estilo.** Los botones de `.align-group` (alineación horizontal `align-left`/`align-center`/`align-right`, vertical `align-top`/`align-middle`/`align-bottom`, estilo `bold`/`italic`/`underline`) pasan a `iconEl(name)` (los grupos `.align-group` inyectan nodo, no string, según el patrón ya usado hoy), sin tocar la lógica de `active`/toggle de cada grupo.
- [x] **`src/ui/cardShapeModal.js` — sustituir los 3 SVG de forma.** Las entradas de `SHAPE_TYPE_OPTIONS` (`circle`/`square`/`square` con esquinas redondeadas) pasan de `icon: '<svg width="18" height="18" ...>'` literal a `icon: iconSvg('shape-circle', { size: 18 })` / `iconSvg('shape-square', { size: 18 })` / `iconSvg('shape-rounded', { size: 18 })`, manteniendo `btn.innerHTML = icon` sin cambios. `shape-rounded` es el único "Lucide + retoque": el módulo define su propio contenido (cuadrado con esquinas redondeadas) en vez de reusar literalmente el `square` de Lucide.
- [x] **`src/ui/componentTypeModal.js` — sustituir los 7 SVG de tipo.** Cada entrada de `COMPONENT_TYPES` con propiedad `icon` (`type-texto`, `type-tablero-simple`, `type-tablero-personalizado`, `type-dado`, `type-documento`, `type-carta`, `type-mazo`) pasa a `icon: iconSvg(name)`; el dado (`type-dado`) mantiene su relleno de puntos con `fill="currentColor" stroke="none"` tal cual, ya que ese matiz vive en el propio dibujo de `dice-5`, no en el contrato del módulo.
- [x] **`src/ui/resourceModal.js` — sustituir zoom +/−/reset.** `ICON_ZOOM_IN`/`ICON_ZOOM_OUT`/`ICON_RESET` (o el literal que reciba `createZoomButton`) pasan a `iconSvg('zoom-in', { size: ICON_SIZE.zoom })` / `iconSvg('zoom-out', ...)` / `iconSvg('zoom-reset', ...)`, sin tocar `createZoomButton` ni el resto del control de zoom/pan.
- [x] **`src/ui/componentRenderer.js` — sustituir los badges de candado y ojo-tachado.** `createLockBadge()`/`createHiddenBadge()` pasan a construir su `<svg>` interno con `iconSvg('locked')`/`iconSvg('hidden')` en vez del literal propio, sin tocar la clase del badge (`component-lock-badge`/`component-hidden-badge`), su posicionamiento ni el criterio de visibilidad permanente.
- [x] **`src/modes/edit/editMode.js` — retirar los 7 helpers `create*Icon()` y usar `iconEl`.** `createCloneIcon`/`createCopyIcon`/`createRemoveIcon`/`createHiddenIcon`/`createGroupIcon`/`createUngroupIcon`/`createFlipIcon` se eliminan; cada llamador (las filas `generalItems`/`specificItems` que pasa a `openContextMenu`) pasa a construir, en el mismo orden en que hoy aparecen: fila "Ocultar"/"Mostrar" → `icon: iconEl('hide')`\|`iconEl('show')` según corresponda; fila "Clonar" → `icon: iconEl('clone')`; fila "Copiar estilo" → `icon: iconEl('copy-style')`; fila "Eliminar" → `icon: iconEl('delete')`; fila "Agrupar" → `icon: iconEl('group')`; fila "Desagrupar" → `icon: iconEl('ungroup')`; fila específica "Voltear cara" (`specificItems`, solo si `allCartas`) → `icon: iconEl('flip')`. Respeta el contrato de `contextMenu.js` (`addRow` exige `SVGElement`, no string).
- [x] **`src/modes/play/playMode.js` — retirar los 4 helpers `create*Icon()` y usar `iconEl`.** `createLockIcon`/`createShuffleIcon`/`createEyeIcon`/`createInsertIcon` se eliminan; los llamadores pasan a `iconEl('lock')`\|`iconEl('unlock')` (según el booleano `open` que hoy recibe `createLockIcon`), `iconEl('shuffle')`, `iconEl('view-contents')`, `iconEl('insert-into-deck')`.
- [x] **`src/ui/visualEditorModal.js` — retirar los 8 helpers `create*Icon()` y usar `iconEl`.** `createDeleteIcon`/`createBringToFrontIcon`/`createSendToBackIcon`/`createRotateIcon`/`createCopyIcon`/`createPasteIcon`/`createMaximizeIcon`/`createRestoreIcon` se eliminan; los llamadores pasan a `iconEl('delete')`/`iconEl('bring-to-front')`/`iconEl('send-to-back')`/`iconEl('rotate')`/`iconEl('copy')`/`iconEl('paste')`/`iconEl('maximize')`/`iconEl('restore')`, incluido el botón de maximizar/restaurar cabecera del modal (`.card-editor-modal__maximize-btn`), sin tocar la lógica de toggle entre ambos iconos.
- [x] **Revisar `add-to-tag`.** Añadir la fila "Añadir a etiqueta" del menú contextual de edición (`src/modes/edit/editMode.js`, fila con `select` pasada a `specificItems`) con `icon: iconEl('tag')`, ya que hoy esa fila no lleva icono — único caso del inventario que introduce un icono nuevo en un sitio que hoy no lo tiene (confirmado con el usuario, ver (a)).
  - **Hallazgo durante implementación (fuera de lo previsto en el plan original):** `src/ui/contextMenu.js`'s `addSelectRow` (la función que pinta filas con `<select>` inline) no aceptaba `icon` en absoluto — a diferencia de `addRow`, que sí lo soporta. Confirmado con el usuario, se extendió `addSelectRow`/`openContextMenu` para aceptar un `icon` opcional en filas de tipo `select`, reutilizando la misma clase `.context-menu__item-icon` que las filas de acción, más una regla CSS nueva en `main.css` (`.context-menu__select-row:has(.context-menu__item-icon)`) para que el icono quede en línea con la etiqueta y el `<select>` seguido debajo a ancho completo.

Orden de implementación: primero `icons.js` (task 1), después el resto en cualquier orden (son sustituciones independientes sitio a sitio).
