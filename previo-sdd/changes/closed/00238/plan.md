## (a) Functional notes

**Out of scope:**

- No se modifica la aplicación entregable ni su build. `src/scripts/build.py` recorre el grafo de imports solo desde `src/main.js` (`ENTRY_MODULE = 'main.js'`, `visit_module(ENTRY_MODULE)`), así que ningún fichero de `src/test/` entra en el HTML autocontenido. `src/scripts/generate-version.py` tampoco cambia.
- No se implementan los tests del "siguiente bloque" de la sección "Funcionalidades candidatas prioritarias" de `description.md` (agrupación, i18n a fondo, sanitización con payloads maliciosos, import/export con conflictos de id, etc.). Este plan cubre solo el andamiaje del framework + los 11 tests de la "batería inicial".
- El caso `sanitization.test.js` mencionado en fases previas **no** se implementa aquí (queda para un cambio posterior; la recomendación de seguridad de incluirlo se deja anotada, no ejecutada).
- No se automatiza la ejecución de `npm test` dentro de `generate-version.py` ni en un hook de git — se deja como gate manual/CI que el desarrollador lanza.
- No se toca `design/docs/features/` (las 40 fichas ya cubren las funcionalidades de la batería inicial). Solo se leen para generar la trazabilidad.
- `npx playwright install` (descarga del binario Chromium) **no** se encadena dentro de `npm test`: se documenta como paso de setup único.

**Doubts resolved with the user:**

- *¿La página de test carga `main.js` real o monta solo lo necesario?* → Sin `main.js` como norma (montaje mínimo explícito por test: 5 contenedores en el DOM + `initI18n()` una vez + llamada directa a `renderEditMode`/`renderPlayMode`). Los tests de arranque/persistencia reproducen la secuencia con las funciones **exportadas** de `core/persistence.js` y `core/state.js`, que es fiel sin ejecutar `main.js`. Si al implementar se detecta un caso de arranque no reproducible sin `main.js`, ese fichero concreto —y solo ese— cargará `main.js` en su propia página (Playwright recarga por fichero, así que el autosave y los ~18 listeners de `main.js` no contaminan a los demás).
- *¿Cómo se aísla cada test del estado y de los listeners del eventBus (Map de módulo compartido)?* → Recarga de página por **fichero** de test: `run.js` navega de nuevo a `runner-page.html?file=<test>` por cada `functional/*.test.js`, de modo que los módulos ES se reinstancian y el `Map` de listeners nace vacío. `beforeEach` dentro del fichero solo hace `resetState()` + limpiar `localStorage`. Coste: 1 navegación por fichero (7 hoy), no por test.
- *¿El generador de `TRACEABILITY.md` va dentro de `run.js` o como comando aparte?* → Dentro de `run.js`, siempre que se lanza `npm test`. Si algún test declara una ficha `NNN` inexistente en `design/docs/features/`, `run.js` termina con exit ≠ 0.
- *Numeración de tests* (heredada de `description.md`): `FT-<NNN>-<nn>`, `<NNN>` = ficha de `design/docs/features/`, `<nn>` = correlativo de dos dígitos.

- [x] **`src/test/run.js` (nuevo) — punto de entrada CLI.** Único fichero que conoce Node y Playwright. Responsabilidades, en orden:
  1. Levantar un servidor HTTP estático con el módulo `http` de Node (sin dependencias), sirviendo el directorio `src/` en `127.0.0.1` y un puerto efímero (`listen(0)`, leer `server.address().port`). El handler resuelve la ruta pedida **dentro de `src/`**: normaliza con `path.normalize`, rechaza (`403`) cualquier ruta que tras normalizar salga de `src/` (`..`), y sirve solo ficheros existentes con su `Content-Type` por extensión (`.html`, `.js` → `text/javascript`, `.json`, `.css`, `.mjs`). `404` si no existe.
  2. `require('playwright').chromium.launch({ headless: true })`; `browser.newContext()`; una `page`.
  3. Descubrir los ficheros de test: `fs.readdirSync('src/test/functional')` filtrando `*.test.js`.
  4. Por **cada** fichero de test: `page.goto(\`http://127.0.0.1:${port}/test/runner-page.html?file=functional/${nombre}\`)`; esperar a que la página exponga el resultado (ver `runner-page.html`), p. ej. `await page.waitForFunction(() => window.__BGF_TEST_RESULTS__ !== undefined, { timeout: 30000 })`; leer `const res = await page.evaluate(() => window.__BGF_TEST_RESULTS__)`.
  5. Acumular por caso: `{ file, name, status: 'pass'|'fail', expected?, actual?, error? }`. En el primer fallo de un fichero, `await page.screenshot({ path: \`src/test/_screenshots/${nombre}.png\`, fullPage: true })`.
  6. Al terminar todos: imprimir resumen `Total: N — OK: X — FALLOS: Y`; por cada fallo, línea con `file › name`, `esperado:` / `obtenido:` (o el `error`).
  7. Invocar el generador de trazabilidad (`generateTraceability(...)`, mismo fichero o `src/test/traceability.js` importado) pasándole la lista de metadatos de test recogidos (ver más abajo cómo se recogen).
  8. `await browser.close()`; `server.close()`.
  9. `process.exit(hayFallos || hayAnomaliaTrazabilidad ? 1 : 0)`.

- [x] **`src/test/runner-page.html` (nuevo) — página cargada en el navegador headless.** Estructura del `<body>` **réplica de `src/index.html`** (necesaria para que `renderEditMode`/`renderPlayMode` no fallen): `<h1 id="app-title"></h1>`, `<div id="edit-toolbar"></div>`, `<div id="mode-switcher"></div>`, `<div id="content"></div>`, `<footer id="app-version"></footer>`, `<script type="application/json" id="initial-state"></script>`.   1. Lee `?file=` de `location.search`.
  2. `import` de `./harness.js` (expone `describe`/`it`/`expect`/`beforeEach`/`afterEach`/`run`/`registerFeature`).
  3. `import` dinámico del fichero de test: `await import('./' + fileParam)` (ruta relativa a `src/test/`, servida por `run.js`).
  4. `const results = await harness.run()`.
  5. `window.__BGF_TEST_RESULTS__ = results;` (array de `{ name, status, expected?, actual?, error? }`) y además `window.__BGF_TEST_FEATURES__` con los metadatos de funcionalidad declarados (ver `harness.js`).

- [x] **`src/test/harness.js` (nuevo) — motor de test, corre en el navegador.** No importa nada de Node ni de Playwright. API:
  - `describe(nombre, fn)` / `it(nombre, fn)` (soporta `fn` `async`) / `beforeEach(fn)` / `afterEach(fn)`: registro en estructuras de módulo.
  - `expect(actual)` → objeto con al menos: `toBe(expected)`, `toEqual(expected)` (comparación profunda para objetos/arrays planos), `toBeTruthy()`, `toBeFalsy()`, `toContain(item)`, `toHaveLength(n)`, `toThrow()`. Cada fallo lanza un `Error` con `{ expected, actual }` adjuntos (propiedades del error) para que `run()` los recoja.
  - `registerFeature({ primary: NNN, secondary: [NNN, ...] = [] })`: lo llama cada fichero de test una vez (a nivel de módulo o dentro del `describe`), declara qué ficha de `design/docs/features/` valida. `harness` lo acumula en `window.__BGF_TEST_FEATURES__` = `{ file, primary, secondary }`.
  - `run()`: ejecuta todos los `describe`/`it` registrados en orden; por cada `it`, corre los `beforeEach` → el cuerpo → los `afterEach` (siempre, aun si el cuerpo falla); captura el resultado. Devuelve `[{ name, status, expected?, actual?, error? }]`.
  - `afterEach` se usa por convención para restaurar mocks (`restoreAllMocks()` de `helpers.js`).

- [x] **`src/test/traceability.js` (nuevo) — `generateTraceability(featuresDir, features, outPath)`.** Corre en Node (lo invoca `run.js`). Pasos:
  1. Leer `featuresDir + '/INDEX.md'` (`design/docs/features/INDEX.md`); extraer, por regex sobre las líneas `- [NNN — Título](NNN-slug.md)`, el conjunto `{ NNN: 'NNN — Título' }` de fichas existentes. Tolerar líneas que no casen (no romper).

No editar a mano: cualquier cambio se sobrescribe. -->`, título, tabla `| Funcionalidad | Tests |` ordenada por `NNN` (formato de fila `NNN — Título` en la izquierda; en la derecha `FT-...`, sufijo ` (secundaria)` donde aplique, o `—` si no hay ninguno), y las dos secciones de anomalías. **Sin fechas ni resultado de la última ejecución.**

## (c) Architecture changes

- **`design/docs/architecture/008-code-conventions.md`** — la línea que dice que `src/test/` contiene ficheros `.json` de ejemplo para importar manualmente (pegando en `#initial-state` o vía `localStorage`) ya no es cierta.
