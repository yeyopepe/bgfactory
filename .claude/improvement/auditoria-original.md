# Auditoría de consumo de tokens — Repositorio SDD con skills
*Ordenado de mayor a menor impacto potencial en ahorro de tokens*

| # | Aspecto a revisar | Tareas específicas | Soluciones potenciales |
|---|---|---|---|
| 1 | **Flujo completo análisis → aplicación** | - Medir tokens totales de un ciclo SDD real de principio a fin<br>- Identificar en qué paso del ciclo se dispara el mayor salto de contexto<br>- Comprobar si el análisis funcional/técnico completo se re-inyecta en cada fase posterior | - Pasar solo el resumen/delta del análisis a la fase de aplicación, no el documento completo<br>- Dividir el ciclo en sub-conversaciones/tareas independientes con handoff explícito (resumen corto) en vez de una sesión continua |
| 2 | **Carga de SKILL.md al inicio de tarea** | - Medir tokens de cada una de las 10-15 SKILL.md<br>- Contar cuántas se leen de media por petición típica vs. cuántas acaban usándose realmente | - Recortar SKILL.md a lo esencial (mover ejemplos largos a archivos aparte, cargados solo si aplica)<br>- Afinar `description` para que la relevancia sea inequívoca y se descarten más rápido las no aplicables |
| 3 | **Solapamiento y ambigüedad de triggers** | - Listar pares de skills cuyas descripciones coinciden en las mismas palabras clave<br>- Simular 5-10 peticiones típicas y contar cuántas SKILL.md "plausiblemente relevantes" se activan por petición | - Diferenciar descripciones con casos de uso concretos y mutuamente excluyentes<br>- Fusionar skills redundantes en una sola con sub-modos, si el solapamiento es sistemático |
| 4 | **Verbosidad de salida de scripts** | - Ejecutar cada script asociado y medir tamaño de su salida estándar<br>- Detectar logs de instalación, listados de directorio o dumps de datos que se cuelan en el contexto | - Añadir flags de salida silenciosa/mínima (`-q`, `--silent`) a los scripts<br>- Redirigir salidas verbosas a fichero y solo mostrar resumen o exit code |
| 5 | **Patrón de re-lectura tras ediciones** | - Contar cuántas veces se repite `view` de un mismo archivo dentro de una tarea de aplicación con múltiples cambios<br>- Verificar si se usa `str_replace` puntual o reescritura completa del archivo | - Agrupar todos los cambios de un archivo en una sola pasada de ediciones antes de re-verificar<br>- Preferir `str_replace` sobre reescritura completa siempre que el cambio sea parcial |
| 6 | **Reutilización de análisis previos** | - Comprobar si la skill de aplicación relee el análisis funcional/técnico completo o solo la parte que le atañe<br>- Revisar si hay versión "resumen ejecutable" del análisis pensada para consumo por otra skill | - Generar, junto al análisis completo, un resumen estructurado corto (JSON/tabla) pensado para ser leído por la skill de aplicación<br>- Versionar análisis y aplicar solo el diff entre versiones |
| 7 | **Tamaño de los documentos de análisis generados** | - Medir longitud media de los informes funcionales/técnicos producidos<br>- Detectar secciones boilerplate que se repiten en todos los informes | - Definir una plantilla mínima obligatoria + secciones opcionales bajo demanda<br>- Externalizar el boilerplate fijo (glosario, convenciones) a un documento de referencia único, no repetido en cada informe |
| 8 | **Cadena de invocación entre skills** | - Mapear qué skills llaman/dependen de otras dentro del mismo ciclo<br>- Contar cuántas SKILL.md se acumulan en cascada en el peor caso | - Aplanar la cadena: que una skill orquestadora cargue solo lo estrictamente necesario en cada sub-paso, no todo el árbol de dependencias de golpe |
| 9 | **Patrón de edición de código (aplicación)** | - Revisar por skill si se usa `str_replace` selectivo o `create_file`/sobrescritura de archivos enteros<br>- Medir tamaño medio de los archivos de código tocados | - Estandarizar en todas las skills de aplicación el uso de ediciones puntuales sobre reescritura completa salvo archivos nuevos |
| 10 | **Número de archivos tocados por tarea** | - Contar archivos abiertos/editados por ciclo SDD completo<br>- Detectar lecturas de archivos no relacionados con el cambio solicitado | - Acotar el scope de búsqueda/lectura al módulo o feature afectado, evitando `view` de directorios completos sin necesidad |
| 11 | **Iteración en generación de documentos largos** | - Revisar si las skills de análisis siguen outline → secciones → revisión y cuántas llamadas intermedias genera cada informe | - Reducir a un único paso para informes de tamaño moderado; reservar el patrón iterativo solo para documentos que superen un umbral de longitud |
| 12 | **Redundancia de instrucciones comunes entre skills** | - Buscar reglas repetidas (naming, estructura de carpetas, formato de commits) en varias SKILL.md | - Centralizar reglas comunes en un único documento de convenciones referenciado por todas las skills, en vez de duplicado en cada una |
| 13 | **Archivos de referencia/plantillas embebidos** | - Detectar ejemplos o plantillas largas incrustadas directamente en el cuerpo de las SKILL.md | - Mover a archivos separados y cargarlos solo cuando la skill los necesite de verdad, no siempre que se lea el SKILL.md |
| 14 | **Uso de memoria/contexto persistente** | - Revisar si alguna skill lee estado o memoria de ejecuciones previas y cuánto contexto añade esa lectura | - Limitar la lectura de memoria a lo estrictamente necesario para la tarea actual, no el histórico completo |
| 15 | **Duplicación entre skill y documentación del repo** | - Comparar contenido de las SKILL.md contra README/docs del proyecto en busca de información repetida | - Referenciar la documentación del repo en vez de duplicarla dentro de la skill |
| 16 | **Coste acumulado en conversaciones largas** | - Estimar cómo crece el contexto en una sesión SDD típica de varias iteraciones | - Recomendar cerrar y abrir nueva conversación al terminar cada ciclo análisis-aplicación completo |
| 17 | **Umbral de activación automática vs. explícita** | - Revisar qué skills se disparan por inferencia de contexto vs. solo con petición explícita | - Restringir a activación explícita las skills de mayor coste (scripts pesados, documentos largos) para evitar activaciones no deseadas |
